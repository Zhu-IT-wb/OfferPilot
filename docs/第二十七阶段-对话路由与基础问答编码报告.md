# 第二十七阶段：对话路由与基础问答编码报告

## 阶段目标

修复 OfferPilot 将“你好”“你是谁”“你能做什么”等普通对话误判为秋招业务动作的问题。

本阶段新增一层对话路由，将普通对话、能力说明、秋招领域问答和真正需要写库的业务动作分开。

## 本阶段改动

- 新增 `backend/app/agents/message_router.py`
  - 负责第一层消息分流。
  - 支持 `smalltalk`、`capability_help`、`domain_question`、`job_action`、`unknown`。

- 新增 `backend/app/agents/general_responder.py`
  - 负责普通回复。
  - 支持问候、身份介绍、能力说明。
  - 对 Java 后端、项目深挖、算法等秋招领域问题，优先调用 LLM，未配置 LLM 时返回可用的本地兜底建议。

- 修改 `backend/app/agents/orchestrator.py`
  - 在业务意图识别前先执行 `MessageRouter`。
  - 只有 `job_action` 会继续进入原来的 `IntentClassifier`。
  - 普通对话不会写入数据库、不会创建日历、不会同步多维表格。

- 修改 `backend/tests/test_agent_orchestrator.py`
  - 覆盖 `你好`、`你是谁`、`你能做什么`、`Java 后端秋招怎么准备`。
  - 确认普通对话不会进入业务意图识别。
  - 确认原有投递/面试确认链路仍可用。

## 当前效果

用户发送：

```text
你好
```

OfferPilot 会正常问候，并提示可用能力。

用户发送：

```text
你是谁？
```

OfferPilot 会介绍自己是秋招执行助手。

用户发送：

```text
你能做什么？
```

OfferPilot 会列出投递记录、面试日历、今日任务、投递查询、面试复盘等能力。

用户发送：

```text
我投递了小红书 Java 后端实习
```

仍会进入原有业务动作识别，要求确认后写入数据库并同步飞书多维表格。

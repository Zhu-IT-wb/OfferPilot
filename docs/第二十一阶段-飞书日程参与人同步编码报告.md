# 第二十一阶段：飞书日程参与人同步编码报告

## 阶段目标

第二十阶段已经实现了 OfferPilot 自动创建专属飞书日历，并把面试安排写入日程。

本阶段继续解决一个关键体验问题：

> 日程虽然由 OfferPilot 应用身份创建，但用户本人也应该被加入到日程中，方便在飞书客户端看到邀请和日历入口。

因此，本阶段采用当前 MVP 最合适的方案：

1. 继续使用应用身份创建 `OfferPilot 秋招日历` 和面试日程。
2. 从飞书消息事件中获取当前用户的 `open_id`。
3. 用户确认执行后，把该 `open_id` 作为日程参与人添加到刚创建的面试日程中。

## 关键实现

### 1. FeishuCalendarService 支持添加日程参与人

新增数据结构：

```python
FeishuCalendarAttendeeResult
```

新增方法：

```python
FeishuCalendarService.add_event_attendee()
```

调用飞书官方接口：

```text
POST /calendar/v4/calendars/:calendar_id/events/:event_id/attendees
```

请求体核心字段：

```json
{
  "attendees": [
    {
      "type": "user",
      "user_id": "ou_xxx"
    }
  ],
  "need_notification": true
}
```

默认使用：

```text
user_id_type=open_id
```

### 2. Agent 编排层注入飞书用户身份

`AgentOrchestrator.handle_message()` 在 `source=feishu` 时，会把当前用户 ID 注入到 slots：

```text
attendee_user_id
attendee_user_id_type
```

这样用户第一次说“后天下午三点腾讯 AI 应用开发一面”时，pending action 会保存这个用户身份；后续用户回复“确认”时，执行工具仍然能拿到同一个 `open_id`。

### 3. 工具层在创建日程后添加参与人

在 `offerpilot_tools._sync_interview_schedule_to_calendar()` 中：

1. 先确保 OfferPilot 专属日历存在。
2. 创建面试日程。
3. 保存 `calendar_event_id`。
4. 如果存在 `attendee_user_id`，调用 `add_event_attendee()`。
5. 回复中补充：

```text
已将你加入日程参与人。
```

如果添加参与人失败，不会回滚已创建的日程，而是在回复中提示失败原因。

## 飞书后台权限要求

除前面已经开通的日历创建、日程创建权限外，本阶段还需要确保开通：

```text
calendar:calendar.event:update
```

或继续使用更大的日历权限：

```text
calendar:calendar
```

否则创建日程可能成功，但添加参与人会失败。

## 当前能力边界

本阶段已经实现：

- 飞书用户发起面试安排后，OfferPilot 能把该用户加入到创建的日程参与人中。
- 创建日程和添加参与人分开处理，便于定位失败点。
- 不需要先做 OAuth 用户授权，适合当前 MVP。

仍需后续增强：

- 当前方案的日程组织者仍是 OfferPilot 应用身份。
- 创建日程时设置的 `reminders` 按飞书规则仅对当前创建身份生效；参与人侧的提醒行为由飞书客户端和用户日历设置决定。
- 如果后续要做到“直接写入用户个人主日历 + 完全按用户身份设置提醒”，需要进入用户 OAuth 授权阶段。

## 3. 接口设计

### 3.1 健康检查接口

请求：

```http
GET /api/health
```

响应：

```json
{
  "status": "ok"
}
```

接口意义：

- 判断后端服务是否启动；
- 后续可用于飞书回调调试前的服务连通性检查；
- 后续部署到服务器后可作为容器或负载均衡健康检查接口。

## 4. 技术选型

本阶段使用：

- Python；
- FastAPI；
- Uvicorn；
- Pytest；
- HTTPX。

选择 FastAPI 的原因：

- 适合快速搭建 API 服务；
- 对 Pydantic schema 支持较好；
- 与 AI 应用和 Agent 编排场景契合；
- 后续接入飞书事件回调和 DeepSeek API 比较直接。

## 6. 当前架构说明

当前后端采用分层目录设计：

```text
api/routes     对外 HTTP 接口
core           配置、安全、日志等基础能力
schemas        请求和响应模型
services       业务服务
agents         Agent 编排逻辑
tools          Tool Calling 工具封装
repositories   数据访问层
models         数据库模型
data           初始题库或种子数据
```

虽然第一阶段只实现了健康检查接口，但目录已经为后续功能留出位置。

后续新增功能时建议遵循：

- 路由层只负责接收请求和返回响应；
- Service 层处理业务逻辑；
- Agent 层处理意图识别、规划、追问、评分等大模型相关流程；
- Tool 层封装可被 Agent 调用的动作；
- Repository 层负责数据库读写；
- Schema 层定义输入输出结构。

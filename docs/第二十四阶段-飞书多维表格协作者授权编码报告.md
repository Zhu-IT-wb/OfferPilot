# 第二十四阶段：飞书多维表格协作者授权编码报告

## 阶段目标

上一阶段 OfferPilot 可以自动创建飞书多维表格并同步投递记录，但多维表格是通过应用身份创建的，用户打开后可能没有编辑权限。

本阶段目标：

1. OfferPilot 同步多维表格成功后，自动将当前飞书用户加入多维表格协作者。
2. 协作者权限为编辑权限。
3. 授权失败不影响投递记录同步，只在机器人回复中提示。
4. 避免重复调用授权 API，成功后在 runtime_settings 中缓存授权结果。

## 实现方案

### 1. 复用飞书事件中的 open_id

飞书事件回调中已经能提取当前发消息用户的 `open_id`。

`AgentOrchestrator` 在 `source=feishu` 时会将它写入 slots：

- `attendee_user_id`
- `attendee_user_id_type`
- `bitable_collaborator_user_id`
- `bitable_collaborator_user_id_type`

其中 `attendee_*` 用于日历参与人同步，`bitable_collaborator_*` 用于多维表格协作者授权。

### 2. 新增云文档权限 API 封装

在 `backend/app/services/feishu_service.py` 中新增：

- `FeishuBitableCollaboratorResult`
- `FeishuBitableService.add_bitable_collaborator`

当前请求形态：

```text
POST /drive/v1/permissions/{app_token}/members
```

查询参数：

```text
type=bitable
need_notification=false
```

请求体：

```json
{
  "member_type": "openid",
  "member_id": "ou_xxx",
  "perm": "edit"
}
```

### 3. 同步链路中自动授权

在 `backend/app/tools/offerpilot_tools.py` 中新增：

- `_sync_bitable_collaborator`
- `_bitable_collaborator_setting_key`

同步流程变为：

```text
写入 SQLite
-> 创建/更新飞书多维表格记录
-> 如果有当前飞书用户 open_id，则授予编辑权限
-> 回复用户同步结果和表格链接
```

授权缓存 key：

```text
feishu.offerpilot_bitable_collaborator.{app_token}.{user_id}
```

## 用户体验

成功后机器人回复会包含：

```text
已同步到飞书多维表格。
已授予你飞书多维表格编辑权限。
打开多维表格：https://feishu.cn/base/...
```

如果授权失败：

```text
暂未授予多维表格编辑权限：...
```

但投递记录仍然会正常写入本地数据库和多维表格。

## 需要的飞书权限

除了多维表格相关权限外，还需要云文档权限管理相关能力。

建议在飞书后台搜索并开通：

- 云文档权限管理
- 增加协作者
- 编辑云文档权限

如果按 scope 展示，重点关注 Drive / 云文档 Permission 相关 scope。

开通后需要重新发布应用版本，否则线上 tenant_access_token 仍可能没有新权限。

## 手动修改多维表格的边界

安全操作：

- 调整列宽
- 拖动字段顺序
- 新建视图
- 调整筛选、排序、分组
- 手动补充备注
- 手动补充来源、优先级、JD 关键词

高风险操作：

- 删除字段
- 重命名字段
- 修改字段类型
- 删除 OfferPilot 自动创建的数据表
- 删除记录
- 修改 `OfferPilot记录ID`

OfferPilot 当前按字段名写入数据，因此字段名和字段类型最好保持稳定。

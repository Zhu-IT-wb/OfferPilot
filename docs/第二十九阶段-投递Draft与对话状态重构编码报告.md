# 第二十九阶段：投递 Draft 与对话状态重构编码报告

## 阶段目标

解决投递管理模块逐渐变成大量 `if/else` 校验规则的问题，将“投递动作理解后的补槽、校验、确认文案”集中到独立模块，降低 Agent 编排层复杂度。

## 本阶段改动

- 新增 `backend/app/agents/application_dialogue.py`。
- 引入投递动作 Draft 流程：
  - 统一清洗投递相关槽位；
  - 统一合并用户补充信息；
  - 统一校验公司、岗位、轮次、具体面试时间；
  - 统一生成投递创建、投递更新、面试安排确认文案。
- `AgentOrchestrator` 不再直接处理投递补槽细节，而是优先委托 `ApplicationDialogueManager`。
- 修复“公司是 xxx 时间是明天下午5点”这类补充回复被错误识别的问题。
- 保留原有工具执行、飞书消息入口、多维表格同步和日历同步机制。

## 改进后的交互

```text
用户：我之前投 Java 后端实习，明天下午邀请我一面
OfferPilot：还缺少公司、具体面试时间（例如明天下午三点）

用户：公司是 测试修改推库 时间是明天下午5点
OfferPilot：识别到公司、轮次、时间，进入确认执行

用户：确认
OfferPilot：更新投递进度并记录面试安排
```

# 第十九阶段：面试时间标准化存储编码报告

## 1. 阶段目标

第十八阶段已经能在创建面试安排后同步飞书日历，但本地 `interview_schedules` 只保存了用户原始时间表达：

```text
明天下午三点
```

这类相对时间有一个问题：过一天后，“明天”含义就变了。

本阶段目标是将面试时间改成“双字段存储”：

```text
start_time: 明天下午三点
start_at: 2026-06-30T15:00:00+08:00
```

其中：

- `start_time` 保存用户原话，方便追溯；
- `start_at` 保存标准化绝对时间，用于飞书日历、提醒和后续查询。

## 2. 本阶段完成内容

### 2.1 面试安排模型增加 start_at

修改文件：

```text
backend/app/models/interview_schedule.py
```

新增字段：

```python
start_at: Optional[str] = None
```

`to_dict()` 也会返回该字段。

### 2.2 Repository 支持保存标准时间

修改文件：

```text
backend/app/repositories/offerpilot_repository.py
backend/app/repositories/sqlite_offerpilot_repository.py
```

`create_interview_schedule(...)` 新增参数：

```python
start_at: Optional[str] = None
```

SQLite 表新增字段：

```text
start_at TEXT
```

并增加轻量迁移：如果本地旧数据库已经存在 `interview_schedules` 表，服务启动时会自动补 `start_at` 列。

### 2.3 工具层创建面试安排时标准化时间

修改文件：

```text
backend/app/tools/offerpilot_tools.py
```

当用户确认面试安排时：

```text
明天早上八点，深信服约我一面
```

工具会：

1. 保留 `start_time=明天早上八点`；
2. 使用 `parse_chinese_datetime(...)` 解析；
3. 写入 `start_at=2026-06-30T08:00:00+08:00`；
4. 后续飞书日历同步优先使用 `start_at`。

### 2.4 飞书日历优先使用 start_at

修改文件：

```text
backend/app/services/feishu_service.py
```

`FeishuCalendarService.create_interview_event(...)` 新增参数：

```python
start_at: Optional[Any] = None
```

创建飞书日历时优先级：

```text
start_at 标准时间
-> 如果没有 start_at，再解析 start_time 原文
```

这样历史数据仍可尽量兼容，新数据则稳定使用绝对时间。

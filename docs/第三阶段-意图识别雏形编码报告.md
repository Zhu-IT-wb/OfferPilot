## 3. 接口设计

### 3.1 意图识别调试接口

请求：

```http
POST /api/debug/intent
Content-Type: application/json
```

请求体：

```json
{
  "message": "新增投递深信服开发实习，明天下午三点一面"
}
```

响应：

```json
{
  "intent": "add_application",
  "confidence": 0.76,
  "slots": {
    "company": "深信服",
    "role": "开发实习",
    "interview_time": "明天下午三点",
    "round": "一面"
  }
}
```

## 5. 实现说明

### 5.1 LLM 优先

`IntentClassifier` 默认复用已有 `LLMService`，通过 system prompt 要求模型只返回严格 JSON：

```json
{
  "intent": "add_application",
  "confidence": 0.86,
  "slots": {
    "company": "深信服",
    "role": "开发实习生",
    "interview_time": "明天下午三点"
  }
}
```

解析后会用 Pydantic 模型校验：

- `intent` 必须属于白名单枚举；
- `confidence` 必须在 `0.0` 到 `1.0` 之间；
- `slots` 必须是对象。

### 5.2 本地规则兜底

由于当前本地环境没有真实 DeepSeek API Key，本阶段在 `LLMConfigurationError` 或模型返回非 JSON 时使用本地规则兜底。

当前规则覆盖了几个最常见的 MVP 输入：

- `今天任务是什么？` -> `get_today_tasks`
- `新增投递深信服开发实习，明天下午三点一面` -> `add_application`
- `我做完反转链表了` -> `complete_task`
- `复盘一下今天的面试` -> `add_interview_review`
- `开始模拟面试，项目问云聚图库` -> `start_mock_interview`

本地规则只作为调试和降级策略，不替代后续 DeepSeek 分类能力。

### 5.3 错误处理

当前行为：

- 未配置 API Key：走本地规则兜底，不阻塞调试接口；
- LLM 服务已配置但上游请求失败：路由返回 `502 Bad Gateway`；
- LLM 返回非 JSON 或字段不合法：走本地规则兜底。

这样可以区分“本地没配 Key”和“模型服务真的异常”，调试体验更清晰。

## 7. 后续开发建议

下一步建议不要立刻接完整飞书链路，而是继续把后端 Agent 编排做薄一层：

1. 定义工具调用结果结构，例如 `ToolResult`；
2. 为 `get_today_tasks`、`add_application`、`complete_task` 先做内存版或本地文件版工具；
3. 新增一个 `AgentOrchestrator`，把“意图识别 -> 选择工具 -> 返回用户消息”串起来；
4. 再接飞书机器人回调和多维表格写入。

这样 OfferPilot 会逐步从“能理解输入”走向“能执行动作”，而不是停留在聊天机器人层面。

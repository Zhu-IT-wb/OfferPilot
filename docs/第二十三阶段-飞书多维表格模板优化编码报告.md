# 第二十三阶段：飞书多维表格模板优化编码报告

## 阶段目标

上一阶段已经实现 OfferPilot 与飞书多维表格的联动，但自动创建的数据表字段全部是文本类型，无法体现多维表格的筛选、分组、看板和日期管理能力。

本阶段将“普通同步表”升级为“秋招投递看板表”：

1. 投递状态、面试轮次、优先级、来源使用单选字段。
2. JD 关键词使用多选字段。
3. 面试开始时间、最后同步时间使用日期时间字段。
4. 提醒分钟使用数字字段。
5. 保留文本字段用于公司、岗位、下一步、备注、日历事件 ID 等信息。

## 新模板字段

升级后的默认数据表为：

- 多维表格：`OfferPilot 秋招投递表`
- 数据表：`投递记录`，旧表迁移时为 `投递记录 Pro`
- 默认视图：`全部投递`

字段设计：

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| OfferPilot记录ID | 文本 | 本地数据库记录 ID |
| 公司 | 文本 | 投递公司 |
| 岗位 | 文本 | 投递岗位 |
| 投递状态 | 单选 | 待投递、已投递、笔试、一面、二面、Offer 等 |
| 状态值 | 文本 | 系统内部状态值 |
| 面试轮次 | 单选 | 笔试、一面、二面、三面、HR 面等 |
| 面试时间文本 | 文本 | 用户原始表达，如“后天下午三点” |
| 面试开始时间 | 日期时间 | 标准化后的时间戳 |
| 提醒分钟 | 数字 | 默认提前 30 分钟 |
| 优先级 | 单选 | 高、中、低 |
| 来源 | 单选 | 飞书助手、官网、内推、Boss直聘等 |
| JD关键词 | 多选 | 岗位关键词 |
| 下一步 | 文本 | OfferPilot 生成的下一步动作 |
| 备注 | 文本 | 后续扩展 |
| 日历事件ID | 文本 | 关联飞书日历事件 |
| 最后同步时间 | 日期时间 | 最近一次同步时间 |

## 迁移策略

如果用户已经创建过旧版全文本表，本阶段不会直接修改旧字段类型，避免破坏已有表结构。

当前策略：

1. 如果 runtime_settings 中没有模板版本，视为旧模板。
2. 下一次同步投递记录时，在同一个多维表格文件中新建 `投递记录 Pro`。
3. 新记录写入新版数据表。
4. record_id 缓存改为按 `table_id + application_id` 隔离，避免新表误用旧表记录 ID。

## 代码改动

### `backend/app/services/feishu_service.py`

- 新增多维表格字段类型常量：
  - 文本
  - 数字
  - 单选
  - 多选
  - 日期时间
- 将 `APPLICATION_TABLE_FIELDS` 从字符串列表升级为字段定义列表。
- 给单选项增加颜色配置，提升飞书展示效果。
- 默认视图名改为 `全部投递`。

### `backend/app/tools/offerpilot_tools.py`

- 新增模板版本：
  - `feishu.offerpilot_bitable_schema_version = v2`
- 新增按表隔离的 record_id 缓存：
  - `feishu.offerpilot_bitable_record_id.{table_id}.{application_id}`
- 同步记录时按字段类型构造值：
  - 单选字段写选项名
  - 多选字段写关键词数组
  - 日期时间字段写毫秒时间戳
  - 数字字段写整数
- 新增“下一步”生成逻辑。

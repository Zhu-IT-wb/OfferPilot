# 第二十二阶段：飞书多维表格联动编码报告

## 阶段目标

本阶段目标是让 OfferPilot 的投递管理模块不只停留在本地 SQLite 数据库中，而是能够同步到飞书多维表格，形成可视化的秋招投递工作台。

当前实现的是 MVP 联动：

1. 创建投递记录后，同步写入飞书多维表格。
2. 更新投递进度或面试安排后，更新同一条多维表格记录。
3. 如果没有配置现成的多维表格，支持自动创建 OfferPilot 专属多维表格和投递记录表。
4. 自动创建出的 app_token、table_id、record_id 会写入 runtime_settings，避免重复创建。

## 主要改动

### 1. 配置项

在 `backend/app/core/config.py` 中新增多维表格配置：

- `FEISHU_BITABLE_SYNC_ENABLED`
- `FEISHU_BITABLE_APP_TOKEN`
- `FEISHU_BITABLE_TABLE_ID`
- `FEISHU_BITABLE_AUTO_CREATE_ENABLED`
- `FEISHU_OFFERPILOT_BITABLE_NAME`
- `FEISHU_OFFERPILOT_BITABLE_TABLE_NAME`

并同步更新 `backend/.env.example`。

### 2. 飞书多维表格服务

在 `backend/app/services/feishu_service.py` 中新增：

- `FeishuBitableService`
- `FeishuBitableAppResult`
- `FeishuBitableTableResult`
- `FeishuBitableRecordResult`

当前封装的飞书能力：

- 创建多维表格：`POST /bitable/v1/apps`
- 创建数据表：`POST /bitable/v1/apps/{app_token}/tables`
- 创建记录：`POST /bitable/v1/apps/{app_token}/tables/{table_id}/records`
- 更新记录：`PUT /bitable/v1/apps/{app_token}/tables/{table_id}/records/{record_id}`

### 3. 投递工具接入多维表格同步

在 `backend/app/tools/offerpilot_tools.py` 中新增：

- `build_default_feishu_bitable_service`
- `_sync_application_to_bitable`
- `_ensure_bitable_for_sync`
- `_build_application_bitable_fields`
- `_format_bitable_sync_lines`

同步字段包括：

- OfferPilot记录ID
- 公司
- 岗位
- 状态
- 状态值
- 轮次
- 面试时间
- 标准开始时间
- 日历事件ID
- JD关键词
- 最后同步说明

## 运行效果

用户在飞书中说：

```text
我投递了腾讯 AI 应用开发岗
```

确认后，OfferPilot 会：

1. 写入本地 SQLite。
2. 如果开启多维表格同步，则确保 OfferPilot 秋招投递表存在。
3. 在飞书多维表格中创建一条投递记录。
4. 回复用户已同步到飞书多维表格。

用户后续说：

```text
后天下午三点腾讯 AI 应用开发岗一面
```

确认后，OfferPilot 会：

1. 更新本地投递状态为一面阶段。
2. 创建面试安排记录。
3. 同步飞书日历提醒。
4. 更新飞书多维表格中同一条投递记录。

## 飞书权限建议

多维表格联动需要在飞书开放平台为应用开通多维表格相关权限。建议先使用应用身份权限，符合当前个人 MVP 的实现方式。

建议权限：

- 创建多维表格
- 查看、评论、编辑和管理多维表格
- 新增、查看、编辑多维表格记录

如果飞书后台按接口展示权限，可以从多维表格相关 API 页面进入权限配置。

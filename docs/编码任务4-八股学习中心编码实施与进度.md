## 2. 产品目标

用户不再需要打开外部八股网站，从长篇文章或 PDF 中自己挑题、判断掌握程度、记录错题。

目标闭环：

```text
飞书机器人推送今日八股
  -> 打开 OfferPilot 学习中心
  -> 一次回答一道题
  -> AI 按评分点分析回答
  -> 展示遗漏点与参考答案
  -> 更新掌握度
  -> 计算下次复习日期
  -> 到期后重新进入每日八股
```

成功标准不是“导入了很多内容”，而是用户能够持续完成：

```text
主动回忆 -> 获得反馈 -> 修正理解 -> 间隔复习 -> 再次验证
```

## 3. 已确认的产品决策

### 3.1 主界面使用网页应用

八股学习需要复杂交互，因此主要界面放在 OfferPilot 网页应用中。

不使用以下能力作为主要学习界面：

- 飞书云文档：适合阅读，不适合逐题状态机和个性化评分；
- 飞书多维表格：适合结构化管理，不适合沉浸答题；
- 连续机器人消息：适合提醒和轻交互，不适合左侧导航、PDF 和长答案；
- 外部八股网站跳转：违背统一入口目标。

### 3.2 最终入口是“OfferPilot 学习中心”

长期页面结构：

```text
OfferPilot 学习中心
├── 今日学习
├── LeetCode
├── 八股复习
├── 复习日历
└── 学习进度
```

八股复习内部：

```text
八股复习
├── 今日复习
├── 薄弱题目
├── 收藏题目
├── 计算机网络
├── 操作系统
├── MySQL
├── Redis
└── 原文资料
```

第一版允许先发布独立 `/study/knowledge` 页面；统一学习中心壳层在八股闭环稳定后完成，避免一开始重构 LeetCode 页面。

### 3.3 默认是一题一卡

用户进入训练后，一次只展示一道题。提交之前不显示答案。

提交后按顺序展示：

1. 总体掌握结论；
2. 回答正确的点；
3. 遗漏或错误的点；
4. 表达建议；
5. 30～60 秒面试简答版；
6. 可折叠的完整解析；
7. 对应原文或 PDF 章节入口；
8. 下一题、重新回答、重点复习等操作。

### 3.4 “每日八股”是调度器，不是第二套页面

机器人只发送聚合提醒：

```text
今日共 5 题：
- 到期复习 2 题
- 历史薄弱题 1 题
- 当前章节新题 2 题

[开始今日八股]
```

答得不好时不立即连续轰炸消息。系统只更新 `next_review_at`，到期后再统一进入每日推送。

### 3.5 PDF 是资料层，不是默认训练层

支持两种页面模式：

- `逐题练习`：默认，一题一卡；
- `原文资料`：完整 PDF、章节或响应式文章。

每道题应保存来源定位：

```text
source_id
source_chapter
source_page_start
source_page_end
source_url
```

点击“查看原文”时直接定位到相关章节或页码。

### 3.6 内容版权边界

不能将第三方网站的整套 PDF 或图文直接提交到公开仓库，除非获得明确授权。

个人学习场景采用以下方式之一：

- 用户自行导入本地 PDF；
- 只存原文链接和页码定位；
- 使用 OfferPilot 原创题目、评分点和参考答案；
- 将受版权保护的本地资料放在 Git 忽略目录，不随代码分发。

## 5. 领域语言

代码中避免使用含义模糊的 `bagua` 作为核心领域名。UI 可以显示“八股复习”，代码使用 `knowledge` 或 `interview_knowledge`。

| 中文概念 | 建议代码名 | 含义 |
| --- | --- | --- |
| 八股题目 | `KnowledgeQuestion` | 可独立回答和评价的问题 |
| 模块 | `KnowledgeModule` | 网络、操作系统、MySQL 等 |
| 章节 | `KnowledgeChapter` | HTTP、TCP、MVCC 等 |
| 评分点 | `KnowledgeRubricPoint` | 必答点、加分点、常见错误 |
| 用户回答 | `KnowledgeAttempt` | 一次文字或语音回答 |
| AI 分析 | `KnowledgeEvaluation` | 命中点、错误点、建议和证据 |
| 掌握进度 | `KnowledgeProgress` | 用户对一道题的长期状态 |
| 每日分配 | `KnowledgeAssignment` | 某天安排给用户的一道题 |
| 资料来源 | `KnowledgeSource` | PDF、文章或原创资料 |
| 练习会话 | `KnowledgeSession` | 一次连续答题过程 |

掌握状态：

```text
unseen
learning
reviewing
mastered
```

分配类型：

```text
new
due_review
weakness
manual
```

## 7. 评分设计

### 7.1 核心原则

模型不直接决定最终分数。模型负责识别：

- 命中了哪些评分点；
- 哪些表述存在事实错误；
- 哪些内容与题目无关；
- 表达是否清晰；
- 每个判断对应用户回答中的哪段证据。

服务端根据结构化结果计算总分。

### 7.2 模型输出草案

```json
{
  "matched_required_point_ids": ["tcp_r1", "tcp_r2"],
  "matched_bonus_point_ids": ["tcp_b1"],
  "triggered_misconception_ids": [],
  "evidence": [
    {
      "point_id": "tcp_r1",
      "quote": "为了确认客户端和服务端都能收发数据"
    }
  ],
  "organization_score": 7,
  "clarity_score": 8,
  "feedback": "结论正确，但没有解释两次握手为什么不够。",
  "suggested_improvement": "先说三个目的，再解释每一次握手验证了什么。"
}
```

必须校验：

- point ID 必须属于当前问题；
- 引用证据必须来自用户回答；
- 数值必须在允许范围内；
- JSON 解析失败时不能生成虚假分数。

### 7.3 服务端计分草案

```text
必答点覆盖：60 分
事实准确性：20 分
表达结构：10 分
表达清晰度：10 分
常见错误：按权重扣分
最终范围：0～100
```

具体公式需要通过固定题目样例测试后再锁定。

### 7.4 掌握度与复习间隔

初始规则：

| 本次得分 | 掌握状态 | 下次复习 |
| ---: | --- | --- |
| 0～59 | learning | 次日 |
| 60～79 | reviewing | 3 天后 |
| 80～89 | reviewing | 7 天后 |
| 90～100 | reviewing | 14 天后 |

连续两次间隔回答达到 80 分以上：

```text
mastery_status = mastered
next_review_at = 30 天后抽查
```

“我不会”：

```text
score = 0
mastery_status = learning
next_review_at = 次日
```

不能因为一次高分直接永久标记已掌握。

## 8. 每日推荐设计

默认每天 5 题：

```text
2 道到期复习
1 道历史薄弱
2 道当前章节新题
```

推荐优先级：

1. 已到期且分数最低；
2. 最近回答中仍有关键遗漏；
3. 用户当前学习章节；
4. 尚未学习的高频题；
5. 其他新题。

需要保证：

- 结果确定性；
- 同一天重复调用返回同一计划；
- 不因服务重启重新分配；
- 题库不足时优雅降级；
- 已完成题不会再次出现在当天未完成列表。

用户提交回答

## 15. 风险与控制

| 风险 | 控制措施 |
| --- | --- |
| LLM 评分漂移 | 结构化 rubric、证据引用、服务端计分、固定样例回归 |
| 题库很多但质量差 | 先做少量高质量题，题目必须有评分点 |
| 参考答案过长 | 默认 30～60 秒简答，完整解析折叠 |
| 用户只看答案不回答 | 提交前隐藏答案，“不会”也记录并安排复习 |
| 推送过多 | 单题只更新队列，固定时间聚合提醒 |
| PDF 移动端体验差 | 优先题目原文定位和响应式章节，PDF 作为补充 |
| 第三方内容版权 | 用户自行导入、外链定位、原创题目，不公开打包 |
| 与 LeetCode 重复实现 | 先复用认证和 owner 规则，稳定后统一学习中心 |
| ngrok 手机拦截 | 开发期允许确认页，正式使用换稳定 HTTPS 域名 |
| ASR 模型快照下线 | 模型 ID 配置化，用固定术语录音集验证新快照后切换环境变量 |
| 语音隐私与存储 | 原始音频不落盘、不入库，转写成功或离开题卡后立即释放 |
| 技术术语转写错误 | 只传模块、章节、题目与非结论性关键词，转写后必须允许编辑 |

# 第十六阶段：投递记录查询与反馈优化编码报告

## 1. 阶段目标

本阶段开始进入投递管理模块的完整闭环建设。

第十五阶段已经支持：

```text
新增投递 / 面试安排
-> 缺字段时追问
-> 用户确认
-> 写入 SQLite
```

但用户写入后还不能自然查询，所以第十六阶段补齐投递记录的读取能力。

目标问题：

```text
我投了哪些公司？
深信服现在什么状态？
最近有哪些面试？
```

## 2. 本阶段完成内容

### 2.1 投递状态展示优化

修改文件：

```text
backend/app/models/application.py
```

新增：

- `APPLICATION_STATUS_LABELS`
- `INTERVIEW_APPLICATION_STATUSES`
- `application_status_label`

将内部状态：

```text
interview_1
interview_2
offer
rejected
```

转换为更适合飞书回复的中文状态：

```text
一面阶段
二面阶段
Offer
已拒绝
```

### 2.2 Repository 增加投递查询能力

修改文件：

```text
backend/app/repositories/offerpilot_repository.py
backend/app/repositories/sqlite_offerpilot_repository.py
```

新增方法：

```python
list_applications(company: Optional[str] = None)
```

支持：

- 查询全部投递记录；
- 按公司名称模糊查询投递记录；
- SQLite 与内存 repository 行为保持一致。

### 2.3 新增查询意图

修改文件：

```text
backend/app/schemas/intent.py
backend/app/agents/intent_classifier.py
```

新增意图：

```text
query_application
```

规则兜底支持：

```text
我投了哪些公司？
深信服现在什么状态？
最近有哪些面试？
```

识别结果示例：

```json
{
  "intent": "query_application",
  "slots": {
    "query_type": "company_status",
    "company": "深信服"
  }
}
```

当前支持的 `query_type`：

```text
list
company_status
upcoming_interviews
```

### 2.4 新增投递查询工具

修改文件：

```text
backend/app/schemas/agent.py
backend/app/tools/offerpilot_tools.py
backend/app/agents/orchestrator.py
```

新增 Agent Action：

```text
query_application
```

新增工具：

```python
query_application(repository, arguments)
```

查询类动作不需要用户确认，会直接读取 repository 并回复。

支持三类回复：

1. 投递列表

```text
当前投递记录：
1. 深信服 - AI 应用开发（二面阶段），二面，时间：今晚
```

2. 单家公司状态

```text
深信服 当前进度：
岗位：AI 应用开发
状态：二面阶段
当前轮次：二面
下一步时间：今晚
```

3. 近期笔试/面试

```text
近期笔试/面试安排：
1. 深信服 - AI 应用开发，二面，今晚
```

### 2.5 创建投递反馈优化

创建投递成功后，回复从一句话改成结构化摘要：

```text
已记录投递：
公司：深信服
岗位：AI 应用开发
状态：二面阶段
轮次：二面
时间：今晚
```

## 6. 当前限制

- 还没有支持投递状态更新，例如“一面过了，约了二面”；
- 还没有同步到飞书多维表格；
- `最近有哪些面试` 目前只查询已有面试/笔试状态记录，不做真实日期排序；
- 投递记录还没有创建时间、更新时间、渠道、批次等字段；
- 同一家公司多个岗位的区分能力仍比较基础。

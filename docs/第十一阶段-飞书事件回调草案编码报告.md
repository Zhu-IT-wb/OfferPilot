# 第十一阶段编码报告：飞书事件回调草案

日期：2026-06-25  
项目：OfferPilot  
任务：新增 `/api/feishu/events` 回调草案，支持 challenge 和文本消息提取  

## 1. 背景

OfferPilot 的真实入口是飞书。需求文档中定义的用户消息处理流程是：

```text
飞书事件回调
  -> 验签
  -> 提取用户消息
  -> 读取用户上下文
  -> 意图识别
  -> 选择工具
  -> 执行工具 
  -> 模型生成回复
  -> 写入日志
  -> 飞书回复用户
```

当前阶段不一次性接完整飞书能力，而是先建立最小事件回调入口：

```text
POST /api/feishu/events
```

本阶段只做：

- URL 验证 `challenge`；
- 提取文本消息；
- 调用 `AgentOrchestrator`；
- 返回调试用处理结果。

暂不做：

- 飞书签名校验；
- 解密 encrypted event；
- 机器人主动回复；
- 飞书多维表格写入；
- 事件去重。

## 3. 接口设计

### 3.1 URL 验证

请求：

```http
POST /api/feishu/events
Content-Type: application/json
```

请求体：

```json
{
  "type": "url_verification",
  "challenge": "challenge_token"
}
```

响应：

```json
{
  "challenge": "challenge_token"
}
```

### 3.2 文本消息事件

请求体示例：

```json
{
  "schema": "2.0",
  "header": {
    "event_type": "im.message.receive_v1"
  },
  "event": {
    "sender": {
      "sender_id": {
        "open_id": "ou_test"
      }
    },
    "message": {
      "message_type": "text",
      "content": "{\"text\":\"今天任务是什么？\"}"
    }
  }
}
```

处理流程：

```text
提取 content.text
-> AgentOrchestrator.handle_message(message, confirmed=False)
-> 返回 AgentResponse
```

响应示例：

```json
{
  "handled": true,
  "event_type": "im.message.receive_v1",
  "message": "今天任务是什么？",
  "user_id": "ou_test",
  "agent_response": {
    "intent": "get_today_tasks",
    "action": "list_today_tasks",
    "reply": "..."
  }
}
```

## 4. 当前实现边界

### 4.1 为什么现在不做完整飞书接入

飞书完整接入需要：

- 配置飞书自建应用；
- 配置事件订阅；
- 暴露公网回调地址；
- 做 challenge 验证；
- 做签名校验；
- 提取消息；
- 调用 Agent；
- 调用飞书发送消息 API 主动回复；
- 处理 retry 和事件去重。

一次做完风险较高，也不利于测试。本阶段先把事件入口和 Agent 调用链路跑通。

### 4.2 为什么返回调试结果

当前还没有接飞书主动回复 API，所以 `/api/feishu/events` 会直接返回处理结果，方便本地测试。

后续正式接入时，接口响应可能只返回确认状态，真实回复会通过飞书消息 API 发回用户。

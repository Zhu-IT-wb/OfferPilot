# 第二十五阶段：飞书多维表格反向同步编码报告

## 阶段目标

上一阶段 OfferPilot 已经可以把本地投递记录同步到飞书多维表格，并授权用户编辑。

但当用户直接在飞书多维表格里修改记录时，本地 SQLite 数据库不会自动变化。本阶段目标是补齐反向同步链路：

```text
用户编辑飞书多维表格
-> 飞书事件回调通知 OfferPilot
-> OfferPilot 读取最新记录
-> 回写本地 SQLite 数据库
```

## 实现内容

### 1. 飞书多维表格记录读取

在 `backend/app/services/feishu_service.py` 中新增：

- `FeishuMessageService._get_json_sync`
- `FeishuBitableService.get_record`
- `FeishuBitableRecordResult.fields`

用于根据 `app_token + table_id + record_id` 拉取飞书多维表格中的最新字段值。

### 2. Repository 支持按 ID 更新投递记录

在 Repository 边界中新增：

- `update_application_by_id`

并分别实现：

- `InMemoryOfferPilotRepository.update_application_by_id`
- `SQLiteOfferPilotRepository.update_application_by_id`

这样反向同步不再依赖公司名匹配，而是优先使用 `OfferPilot记录ID`。

### 3. 新增反向同步服务

新增文件：

```text
backend/app/services/bitable_sync_service.py
```

核心方法：

```python
sync_bitable_record_to_repository(...)
```

支持两类场景：

1. 修改已有记录：根据 `OfferPilot记录ID` 或 record_id 映射更新本地投递。
2. 手动新增记录：如果飞书表格行里有公司和岗位，则在本地数据库创建投递记录。

当前同步字段：

- 公司
- 岗位
- 投递状态
- 面试轮次
- 面试时间文本
- JD关键词

### 4. 飞书回调路由识别多维表格事件

`backend/app/api/routes/feishu.py` 中的 `/api/feishu/events` 现在支持两类事件：

1. `im.message.receive_v1`：飞书聊天消息，继续交给 Agent。
2. 多维表格记录变更事件：提取 `app_token / table_id / record_id` 后执行反向同步。

如果事件中包含多个 `record_id`，会逐条处理。

## 飞书后台仍需配置

代码已经具备处理能力，但飞书不会默认把多维表格改动推给后端。

还需要在飞书开放平台中：

1. 进入 `事件与回调`。
2. 添加多维表格/云文档相关事件。
3. 选择“记录变更”或类似名称的事件。
4. 确认请求地址仍是当前 cloudflared 地址：

```text
https://xxx.trycloudflare.com/api/feishu/events
```

如果没有订阅该事件，用户在多维表格里编辑后，后端不会收到任何请求。

## 边界说明

安全操作：

- 修改公司、岗位、状态、轮次、面试时间、JD关键词
- 在表格中手动新增一行，并填写公司和岗位
- 调整列宽、视图、筛选、排序

需要谨慎：

- 删除 `OfferPilot记录ID` 字段
- 重命名关键字段
- 修改关键字段类型
- 删除数据表
- 删除多维表格应用

OfferPilot 当前按字段名读取数据，因此字段名需要保持稳定。

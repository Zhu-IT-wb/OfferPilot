# 第二十八阶段：面试时间追问与日历提醒确认编码报告

## 阶段目标

修复飞书对话中面试安排记录的两个交互问题：

1. 用户只说“明天下午”这类不完整时间时，不应直接更新投递进度或创建面试安排。
2. 创建日历提醒前，应允许用户在确认执行前选择“不需要提醒”。

## 本阶段改动

- 在 Agent 编排层增加面试时间完整性校验：只有能解析出具体日期和小时的时间表达，才允许进入待确认更新流程。
- 优化补槽逻辑：当系统缺少公司名时，不再把“明天下午三点”这类时间补成公司。
- 增加日历提醒偏好识别：用户可以在待确认阶段回复“不需要提醒”“不用日历”等表达来关闭本次日历同步。
- 优化工具执行结果文案：用户选择不提醒时，回复“已记录面试安排，未添加飞书日历提醒”。
- 增加回归测试，覆盖“不完整时间追问”和“确认前关闭日历提醒”两条核心路径。

## 当前交互效果

示例：

```text
用户：我之前投递的美团 Java 后端实习，明天下午邀请我一面
OfferPilot：还缺少具体面试时间（例如明天下午三点）

用户：明天下午三点
OfferPilot：默认会同步飞书日历并提前 30 分钟提醒；如果不需要，可以先回复“不需要提醒”，否则回复“确认”执行。

用户：不需要提醒
OfferPilot：不需要同步飞书日历提醒，执行前需要你确认。

用户：确认
OfferPilot：已更新投递进度，并记录面试安排，未添加飞书日历提醒。
```

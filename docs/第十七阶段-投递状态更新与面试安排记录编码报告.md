# 第十七阶段：投递状态更新与面试安排记录编码报告

## 1. 阶段目标

第十六阶段已经支持查询投递记录，但投递流程还只能“新增”和“查询”，不能持续推进状态。

本阶段目标是补齐投递管理模块中的状态更新能力，让用户可以在飞书里继续说：

```text
明天早上八点，深信服约我一面
深信服一面过了
深信服挂了
深信服给 offer 了
最近有哪些面试？
```

OfferPilot 需要先识别这是对已有投递的更新，经过用户确认后再写入数据库。

## 2. 本阶段完成内容

### 2.1 扩展投递状态模型

修改文件：

```text
backend/app/models/application.py
```

新增状态：

```text
written_test_passed
interview_1_passed
interview_2_passed
interview_3_passed
```

并补充状态映射方法：

```python
application_status_from_round(round_name)
application_passed_status_from_round(round_name)
```

这样 `一面` 可以映射为 `interview_1`，`一面过了` 可以映射为 `interview_1_passed`。

### 2.2 新增面试安排模型

新增文件：

```text
backend/app/models/interview_schedule.py
```

新增 `InterviewSchedule`，用于记录：

- 公司；
- 岗位；
- 面试轮次；
- 面试时间；
- 默认提醒时间；
- 后续飞书日历事件 ID。

当前默认提醒为：

```text
提前 30 分钟
```

说明：本阶段只记录面试安排，还没有真正调用飞书日历 API。

### 2.3 Repository 增加更新与面试安排能力

修改文件：

```text
backend/app/repositories/offerpilot_repository.py
backend/app/repositories/sqlite_offerpilot_repository.py
```

新增能力：

```python
update_application(...)
create_interview_schedule(...)
list_interview_schedules(...)
```

SQLite 新增数据表：

```text
interview_schedules
```

用于后续同步飞书日历和提醒。

### 2.4 增强意图识别

修改文件：

```text
backend/app/agents/intent_classifier.py
```

增强 `update_application` 规则兜底。

示例：

```text
明天早上八点，深信服约我一面
```

识别为：

```json
{
  "intent": "update_application",
  "slots": {
    "company": "深信服",
    "round": "一面",
    "interview_time": "明天早上八点",
    "update_type": "schedule_interview",
    "status": "interview_1"
  }
}
```

```text
深信服一面过了
```

识别为：

```json
{
  "intent": "update_application",
  "slots": {
    "company": "深信服",
    "round": "一面",
    "update_type": "pass_round",
    "status": "interview_1_passed"
  }
}
```

### 2.5 新增投递更新工具

修改文件：

```text
backend/app/tools/offerpilot_tools.py
```

注册并实现：

```text
update_application
```

支持：

- 安排面试；
- 更新笔试/面试通过；
- 更新拒绝/挂掉；
- 更新 Offer；
- 找不到公司时给出明确提示。

当用户确认面试安排后，会同时：

1. 更新投递状态；
2. 写入一条面试安排；
3. 回复默认提前 30 分钟提醒。

### 2.6 Agent 编排支持更新确认

修改文件：

```text
backend/app/agents/orchestrator.py
```

`update_application` 属于写操作，仍然需要用户确认。

流程示例：

```text
用户：明天早上八点，深信服约我一面
OfferPilot：我识别到你要记录面试安排，公司是深信服，轮次是一面，时间是明天早上八点。执行前需要你确认。
用户：确认
OfferPilot：已更新投递进度，并记录面试安排，默认提前 30 分钟提醒。
```

### 2.7 查询近期面试优先读取面试安排

修改文件：

```text
backend/app/tools/offerpilot_tools.py
```

`query_application` 在 `query_type=upcoming_interviews` 时，会读取 `interview_schedules`。

回复示例：

```text
近期笔试/面试安排：
1. 深信服 - AI 应用开发，一面，明天早上八点，提前 30 分钟提醒
```

## 5. 当前限制

- 面试时间仍保存为用户原始表达，例如 `明天早上八点`，还没有解析成标准时间戳；
- 已记录默认提前 30 分钟提醒，但还没有创建飞书日历事件；
- 面试安排还没有同步到飞书多维表格；
- 复杂表达仍主要依赖 DeepSeek，规则兜底覆盖的是高频场景。
